# Domain docs

This repository uses a single context:
- GLOSSARY.md at the repository root.
- Architecture decision records under docs/adr/.

Before exploring, read the glossary and relevant ADRs when present.
If absent, proceed silently. Create domain documentation as terms
and decisions are resolved, rather than creating empty placeholders.

Use glossary terms consistently in code, tests, and issues.
Identify conflicts with existing ADRs explicitly before proposing changes.
